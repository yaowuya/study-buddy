### High

#### Edit page does not implement the confirmed complete editing and conflict workflow

- Evidence: `client/src/pages/parent/homework-plan-edit.vue:30-36` compresses the entire workflow into untyped one-line handlers; it lacks field-level date/duration errors, first-error positioning, a dedicated 409 refresh panel/action, and submission lock on back/delete. The save catch only displays `e.message`. No edit-page tests exist under `client/tests/pages/`.
- Failure scenario: another parent updates the plan while this page is open. Saving receives 409, but the user only gets a generic toast and cannot perform the confirmed “refresh and retry” flow. Invalid end dates or duration also produce only a generic toast/server error rather than the confirmed inline feedback. Pressing the platform/native back action is not intercepted, so dirty changes can be lost without the confirmation shown by the custom back button.
- Source requirement: frontend design `01-data-flow-and-pages.md` edit workflow and `02-components-and-visual-contract.md` interaction checks; frontend-009/010 task contracts.
- Suggested fix direction: add `onBackPress` dirty-state interception; typed form/error state; client date/duration validation; 422 mapping; explicit 409 panel with reload action that preserves local edits until confirmed; disable back/delete while saving; add the planned edit page tests.

### Medium

#### Frontend implementation has only four tests and omits all planned page/store/component behavior tests

- Evidence: `client/tests` contains only `utils/local-date.spec.ts` and `api/homework-plans.spec.ts`. Missing planned specs include Store, DictationConfig, task-create, HomeworkPlanCard, Dashboard, student-home and edit page.
- Failure scenario: a later refactor can break materialize-before-fetch ordering, conditional hidden dictation DOM, duplicate submit prevention, logout clearing, delete confirmation, or plan-card states while all current frontend tests still pass.
- Source requirement: frontend plan tasks frontend-003 through frontend-010 and frontend coverage matrix.
- Suggested fix direction: implement the exact planned Vitest specs with meaningful assertions before archive.

- Source requirement: backend design concurrency contract and backend-006.
- Suggested fix direction: run the existing suite against an isolated PostgreSQL test database and record passing evidence.
