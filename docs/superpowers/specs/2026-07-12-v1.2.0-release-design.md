# Study Buddy 1.2.0 发布设计

## 目标

将项目版本统一升级到 1.2.0，检查并修正后端 Docker 部署配置，发布 1.2.0 更新日志，并使 README 准确反映当前功能、版本和部署方式。本次只提交并推送发布文件，不创建 Git 标签或 GitHub Release。

## 版本策略

- 新增 `app/core/version.py`，以 `APP_VERSION = "1.2.0"` 作为后端运行时唯一版本来源。
- FastAPI/OpenAPI 使用 `APP_VERSION`，`/health` 同时返回状态与版本。
- UniApp `manifest.json` 使用 `versionName: "1.2.0"`、`versionCode: "120"`。
- `client/package.json`、`admin/package.json` 及对应 lockfile 顶层版本同步为 `1.2.0`。
- Docker 镜像版本通过 `ARG APP_VERSION=1.2.0` 和 OCI `org.opencontainers.image.version` 标签暴露。

## Docker 设计

### Dockerfile

- 保留 Python 3.11 slim、非 root 用户、自动迁移和 Gunicorn/Uvicorn worker 模式。
- 只执行 `pip install -r requirements.txt`，删除重复安装已在 requirements 中声明的 Gunicorn/Uvicorn。
- 添加 `ARG APP_VERSION`、`APP_VERSION` 环境变量和 OCI version 标签。
- 保留 `/app/tmp`、`/app/logs` 与端口 8000。

### docker-compose.yml

- 添加 `image: studybuddy-api:1.2.0`，使本地构建产物具有明确版本。
- 将容器名从历史遗留的 `studybuddy-api-2.0` 改为稳定名称 `studybuddy-api`，避免容器名与应用版本耦合。
- 保留外部 MySQL、`.env`、日志和临时目录挂载。
- 使用 Python 标准库请求 `/health` 的健康检查，不引入 curl 依赖。
- 不把 UniApp 源码/产物打入后端镜像；管理后台继续使用已提交的 `static/admin-dist`。
